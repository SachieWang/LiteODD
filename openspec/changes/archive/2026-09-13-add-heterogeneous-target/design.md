## Context

「可复用」当前只有单一同源样例(`targets/dsh`)作证据,已量化出类型/关系覆盖缺口,且已发生无人察觉的本体漂移(5 个未声明关系类型)。动机见 proposal.md。约束:meta-only 吸收纪律、add-only、KISS、与 OpenSpec/harness 解耦。

本 change 是**实践**而非方法论改动:它是去**取证据**,不是去改契约。故 `skip_specs: true`。

## Goals / Non-Goals

**Goals:**
- 用**已冻结的 meta 层**在第二个、异质的目标上跑完五层全链。
- 把"通用性"从声称变成**可 diff 的事实**:要么 meta 零改动跑通,要么精确定位改不动的地方。
- 为 frame 关系类型的**语义与方向约定**提供依据(该决定此前被刻意推迟,见 `relation-conformance-report` 的 Open Questions)。

**Non-Goals:**
- **不在本 change 内修改任何 meta 层文件**。必须改的话,另开方法论 change(见 F5)。
- 不用模拟案例代替真实目标。`docs/tutorial.md` 的 eShop-demo 是**讲解用虚构案例**,不构成通用性证据;而且编造来源现在会被 `provenance_resolvable` 拦下。
- 不改动 `targets/dsh`(它是既有的喂料源,不是本 change 的对象)。
- 不改 `frame.yaml` 的关系语义(见 Decisions 4)。

## Decisions

1. **目标必须异质,至少覆盖三个维度中的两个。**
   - 领域异质:非 agent、非开发者工具(零售订单 / 医疗排班 / 工业设备台账 等);
   - 类型异质:逼出 `Component` 与 `ContextBoundary` 的真实用法(`targets/dsh` 从未实例化这两个类型);
   - 规模异质:实例与产物显著多于现状(现为 14 实例 / 11 产物)。

2. **meta 冻结是本 change 的方法论核心,而不是附带约束。**
   把"通用性"变成 `git diff` 可达的事实:验收 F4 就是"meta 层零改动"。这一步把形容词换成证据,是本 change 相对于"再做一遍练习"的全部区别。

3. **验收 F3 允许"不可达判定",但禁止静默忽略。**
   若某个类型/关系在本领域**确实**用不上,必须显式记为"不可达判定"并给出理由。静默留空就等于把缺口重新藏起来——那正是本 change 要消除的东西。

4. **本 change 不给 frame 的关系类型定语义,只收集依据。**
   frame 的 8 个关系类型目前是**光秃秃的 id**(无含义、无 `from`/`to` 方向约定),而三个 dsh domain model 已经自发用了 5 个别的词(`applies`/`consumes`/`hasScope`/`isA`/`uses`)。在**单一同源目标**上据此定通用本体词汇,正是"被单一目标拟合"。等 F 的异质数据出来,词汇该扩该并才有依据。

5. **优先走最小切片。**
   第一轮不必是完整项目:选一个真实但小的领域(10~20 实例),先只跑 Layer 0 + Layer 1 的需求与建模两件。这能以远低于完整项目的成本拿到核心结论(通用 or 不通用);需要完整项目再扩容。

## Risks / Trade-offs

- [可能需要真实领域输入,成本最高] → 最小切片(D5)先把成本压到可承受;真实来源可用 `ontology/sources.yaml` 登记。
- [跑不完] → **这不是失败,而是本 change 的主要产出形态**:跑不完的地方精确定位了通用性的边界,直接转入 F5。
- [形式主义:为过门而堆产物] → 用 F3(覆盖度断言,含不可达判定)+ 真实来源要求(`provenance_resolvable` 强制)对抗。
- [F 自己也用上未声明的关系类型] → **这正是要记录的证据**,不是要绕过的障碍;按 F5 记成候选。
- [有人图省事直接改 frame 让 F 过门] → F4 的 `git diff` 断言把这条路显式堵死。

## Migration Plan

1. 选领域 + 建对象层三文件。2. 跑 Layer 0。3. 用三技能产出四类产物。4. 跑 Layer 2 全链过门。5. 跑 Layer 4 verify + report。6. 按 F1–F5 逐条验收。7. 结论与后续 change。回滚:对象层默认不入库,删除即可。
